# Architecture

The Claude Code plugin for Telmoni: a hook that records each turn of a person's Claude Code sessions as a run, metadata only unless the developer turns content on, through the platform's TypeScript SDK ([`telmoni/telmoni`](https://github.com/telmoni/telmoni), `sdk/typescript`). The repository is the plugin: its marketplace names itself, Claude Code clones it, and the hook runs from the clone with Node, from the bundles in `dist/`, which tsup builds from `src/` and the SDK and which are committed. Nothing is built, installed or fetched on a person's machine; there is nothing to publish.

## Purpose and scope

One run a turn, from the person's prompt to the agent's last reply or the person's interruption, of the agent `claude-code`, in the session Claude Code names: its model calls with their tokens, its tool calls, its subagents as steps holding their own calls and their own subagents' steps, its compactions, the skills it ran and the tags the developer set, each with its times and whether it failed or was cancelled. The plugin reads Claude Code's own transcript after the fact; it changes nothing in a session, adds no tool and no prompt, and never fails or slows a turn. It records Claude Code alone: where another editor runs Claude Code's hooks, it does nothing. What becomes of a run past ingest is Telmoni's.

## How Claude Code loads it

- **The marketplace**, `.claude-plugin/marketplace.json`: `telmoni-plugins`, listing one plugin, `telmoni-observability`, whose source is `./`, the repository itself. `claude plugin marketplace add telmoni/claude-code-observability-plugin` clones it; `claude plugin install telmoni-observability@telmoni-plugins` copies it at its head.
- **The manifest**, `.claude-plugin/plugin.json`: the name `telmoni-observability`, the version, and five `userConfig` settings Claude Code asks for at install and `/plugin configure` changes: `TELMONI_API_KEY` (a string, `sensitive`, so Claude Code keeps it with its credentials), `TELMONI_ENDPOINT` (a string, empty by default), `TELMONI_CAPTURE_CONTENT` (a boolean, `false` by default), and `TELMONI_SCRUB_SECRETS` and `TELMONI_SCRUB_PII` (booleans, `true` by default). Claude Code hands each to the hook's environment as `CLAUDE_PLUGIN_OPTION_<name>`, its default where none was set.
- **The hooks file**, `hooks/hooks.json`, registers one command, the same for each of three events, with no matcher:
  - `Stop`, as a turn stops: the turn just ended, and any before it still held;
  - `StopFailure`, as an API error ends a turn: its payload's `error` names the kind;
  - `SessionEnd`, as the session ends: every turn left, as it stands.
- **The command**: `node "${CLAUDE_PLUGIN_ROOT}/dist/hook.mjs" || true`: the command exits 0 whatever Node returns, or where there is no `node` on the `PATH`, since a `Stop` hook's exit 2 would send Claude back to work.
- **The skill**, `skills/tag/SKILL.md`: `tag`, which Claude Code names `telmoni-observability:tag`; it runs nothing (below, *Tags*).

## Processes: the hook and its worker

`dist/hook.mjs`, built from `src/bin/hook.ts` and `src/hook.ts`, loads no SDK, so nothing heavier than the payload's reading stands between the event and the return. It reads the event from stdin (`payload.ts`) and keeps only what names the work: the session id (`[A-Za-z0-9._-]{1,128}`, else nothing is done), the transcript's path with `~` expanded, the event, a `StopFailure`'s error kind (`unknown` where it names none fit to keep), and `busy`, whether `background_tasks` lists one of kind `subagent`, `workflow` or `teammate`. An event not of the three, a payload not an object, no session or no path: nothing is done. Inside another editor running Claude Code's hooks, known by `CURSOR_VERSION` or `CURSOR_PROJECT_DIR` in the environment or `conversation_id`, `generation_id` or `cursor_version` in the payload, nothing is done either.

It then starts the worker, `dist/worker.mjs` beside it, on the hook's own Node (`process.execPath`), and returns at once. The worker is detached, in a session of its own (`detached`; on Windows with `windowsHide`, so no window opens), its stdout discarded and its stderr appended to `hook.log`. The payload goes by the worker's stdin, never its arguments, which every user of the machine can read and which would name the transcript. Any fault in the hook is swallowed: it returns 0 even with no folder to write.

The worker's bundle carries the SDK, `telmoni`, at the version `package-lock.json` holds, and the OpenTelemetry it is built on, so nothing is fetched when it first runs. The worker (`worker.ts`) reads the settings; takes the session's lock; waits for the transcript to settle (no change of size or mtime for 0.5 s, 3 s at most), since a hook can run before the turn's last rows land; reads the rows written since the last hook; sends each turn that is complete; remembers the rest; then sends what other sessions left (below, *Delivery*) and sweeps quiet locks. It returns 0 whatever happens, a fault being one line in the log naming its type, and exits once its state is saved, whatever a socket or a timer of the SDK's still holds.

## What it reads

A transcript is JSON Lines, each row an object, read from a byte offset; a line that is not UTF-8 or not JSON, or not yet whole, is passed over, and a file shorter than the offset was replaced and is read from its start. All of it goes through `transcript.ts`. Of each row:

- the row: `type`, `uuid`, `sessionId`, `timestamp` (ISO 8601, read as UTC where it names no zone), `version` (the Claude Code that wrote it), and `cwd`, only to find the tags file (below);
- the flags of rows Claude Code writes in the person's place: `isMeta`, `isCompactSummary`, `turnCompanion`, `isSidechain`; and `origin.kind` (`human`, `task-notification`, `peer`), with a peer's `origin.handback` and `origin.from`, the subagent whose report it hands back, never `handbackReportText`;
- of a reply (`type` and `message.role` both `assistant`): `message.id`, `message.model`, `message.stop_reason` (`tool_use` and `pause_turn` wait on more; anything else ends the model's turn), and `message.usage`: `input_tokens`, `output_tokens`, `cache_read_input_tokens`, and the cache's writes as the sum of `cache_creation`'s counts, else `cache_creation_input_tokens`; an API error by `isApiErrorMessage` and the kind in `error` (a word of at most 64 characters with no space, else `ApiError`), never its message;
- of each `tool_use` block in a reply: `id`, `name`, and of its `input`, `skill` from a `Skill` call, `subagent_type` and `run_in_background` from an `Agent` or `Task` call, and `args` from a `Skill` call whose `skill` is `telmoni-observability:tag`; nothing else;
- of each `tool_result` block: `tool_use_id` and `is_error`; and of the row's `toolUseResult`, Claude Code's own record of the result, only `interrupted`, and whether it says a subagent went on in the background (`status` `async_launched` or `teammate_spawned`, or `isAsync`) with its `agentId`;
- of an `attachment` row, whether it is a `hook_blocking_error` whose `hookEvent` is `Stop`;
- of a user row's text (its `content` as a string, or its first text block that says anything, since an image comes behind an empty one), the first 64 characters, for the markers Claude Code writes there: `[Request interrupted by user` and `[Request interrupted by user for tool use]`, `<task-notification>`, `<local-command-stdout>`, `<local-command-caveat>`, `<system-reminder>`; of a notice, the id between `<tool-use-id>` tags; of a row whose first 256 characters hold `<command-name>/telmoni-observability:tag</command-name>`, what lies between `<command-args>` tags; and of its blocks, whether one is an image. Nothing of that text is kept.

Names are kept as plain names within ingest's caps (`names.ts`), a character being a code point, so no cut splits one: a model's name is cut to 128 characters, a model named by a path goes as its weights file's name (`.gguf`, `.ggml`, `.bin`, `.safetensors`, `.llamafile`) or `unknown`, as does one with a control character; a tool's name of anything but word characters and `.:@+-` goes as `unknown`, else cut to 145; a skill's name or a subagent's kind is kept only as 1 to 64 word characters and `.:-`, else not at all.

**Subagents.** A session's subagent transcripts are in the folder named after its transcript, less `.jsonl`, under `subagents/`, at any depth: each `<name>.meta.json` beside its `<name>.jsonl`. Of the meta file the plugin reads `toolUseId`, the call that started the subagent, `agentType` and `finished`, never `description`; a meta file without its transcript is passed over. A subagent's own subagents are found the same way, their meta files beside the first's (Claude Code marks each with its `spawnDepth`, which is not read), each by the call in the transcript above it that started it. A subagent's transcript is read whole each time its turn is built, the same reader, its rows one span of work (`turns.collect`).

**With content on** (below, *Configuration*), `transcript.ts` also reads the conversation, as the GenAI conventions' parts: the prompt's text and each base64 image as a blob of its bytes with its `media_type` (`prompt_parts`); each reply's `thinking` blocks in plain text, never a `redacted_thinking` block, its text and its tool calls with their `input` (`reply_parts`); each tool result's `content`, never `toolUseResult`, which names files (`tool_outputs`); a subagent's task, the `prompt` its launching call gave it (`subagent_task`); and a compaction's summary, its text read as a prompt's is (`summary_parts`). With it off, none of that is read.

## How turns are cut

`turns.assemble` walks the rows in order. A row whose `sessionId` is another session's is passed over, as a fork copies its history: that session recorded it. A prompt the person gave opens a turn and closes the one before it: a `user` row that is none of Claude Code's flagged rows, holds no tool result, starts with none of the markers above, and says something, or is the person's by `origin.kind` `human`, or holds an image. So does a `Stop` hook that blocked the stop, marked by its `hook_blocking_error` attachment: the work it carries on has no prompt, and is a run of its own, named by that row, since the turn before it may already have been sent at that `Stop`. A compaction's summary, injected context and a command's output open nothing.

Within a turn (`Turn.feed`):

- **Model calls.** The rows of one `message.id` are one call, timed from the event before its first row to its last, its usage the latest given, failed with an API error's kind where a row carries one. With content on its rows' parts gather in order, and it is given what is new to it: the turn's first call the prompt, a subagent's first its task, and each after the results of the tool calls since the call before, each a `tool_call_response` part, together one `tool` message. The first call of work a blocking `Stop` hook carries on is given nothing, the hook's reason being never read; nor is any call given injected context, a meta row or a task's notice.
- **Compactions.** A compaction's summary row (`isCompactSummary`) is a step from the event before it to the row, the model call after it starting there. It is kept once a later model call of the turn follows it, so a turn's record never depends on when its hook ran: one with no model call after it, as a manual `/compact` between turns has, is not recorded, nor does it move the turn's end. Only the session's own transcript is read for them; a subagent's summary row is passed over.
- **Tool calls.** Each opens at its reply and closes at its result: failed (`ToolError`) where the result's `is_error` says so, cancelled where `interrupted` says so; a refusal is an error result followed by the tool-use interruption marker, which turns the calls that result answered from failed to cancelled. A call never answered is cancelled with the turn.
- **Interruptions.** `[Request interrupted by user` ends the turn cancelled unless a reply follows it, and cancels the model call of a reply it cuts short.
- **Background subagents.** A tool result naming an `agentId` launched in the background marks its call as background. A task's notice naming the call, or that subagent's report handed back, whichever comes first, marks it answered, in whichever later turn it lands; the next reply after it marks it replied to.

A turn is complete, and sent, when nothing can still change it (`turns.isComplete`): every background call has been answered and replied to; no subagent it ran has a meta file saying `finished` is `false` (one naming no `finished` is not waited on); at a `Stop`, a turn a blocking `Stop` hook began, still the last, has ended in a reply that ends the model's turn or in an interruption, since that hook can return inside the worker's settle wait and the run be read under way at the very `Stop` it followed; and, if it is the last turn, the payload is not `busy`. At `SessionEnd` every turn is complete as it stands. A turn with no model call and no tool call is passed over. The first turn not complete holds every turn after it, the log saying `held <run id>: its turn is not over yet` at each hook that holds it.

## What it sends

One run a turn, built as plain values by `record.ts` (which is what the state keeps, its keys in snake_case as the state has always written them) and turned into the SDK's `RunRecord`, `ModelCallRecord`, `ToolCallRecord` and `StepRecord` by `send.ts`, and sent through `recordRun`.

- **Ids.** The run's id is `uuid5` of `session:prompt` under the plugin's own namespace (`uuid5(NAMESPACE_URL, "https://telmoni.com/claude-observability-plugin")`, the repository's name before its rename, kept so a turn's id never changes), the prompt being the opening row's `uuid` (or its offset where it has none). The SDK makes the run's id its trace's, and each span's id from it and the span's place, so a turn sent twice is stored once. The worker also remembers the newest 500 ids it sent, and passes over a turn among them.
- **The run.** The agent `claude-code`; the session; the span from the prompt to the last reply, result or interruption; `release`, the version of Claude Code that wrote the prompt row, given to the SDK's `Config`; `cancelled` where an interruption ended it; `error_type`, the last model call's error kind, else, for a still-open turn at `StopFailure`, the hook's; and the tags (below), `skills` first, naming the skills the turn ran, joined by commas, cut at a name to 256 characters.
- **Model calls.** Each with its model, its usage, and its provider as the GenAI conventions and the price table name it: `aws.bedrock`, `gcp.vertex_ai` or `azure.ai.inference` where Claude Code's `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` or `CLAUDE_CODE_USE_FOUNDRY` is `1` or `true`, else `anthropic` (a kept run of an older version naming none goes as `anthropic`). Its input counts the cache's reads and writes, as the conventions do, where Anthropic's own `input_tokens` leaves them out; the reads and writes go beside it too.
- **Tool calls** by name. **Subagents**, a call that started a subagent with a transcript, as a step named `subagent <kind>` (the call's `subagent_type`, else the meta file's `agentType`, else plain `subagent`), holding the subagent's own model and tool calls, timed to the later of its result and its last row. A call inside a subagent that started one of its own is a step in turn, nested in the first's, as deep as the SDK nests steps (16, the run's own at 1, past which it refuses a record whole): deeper, the call goes as a plain tool call. So does a call whose subagent the run has expanded already, so a meta file naming a call of its own transcript ends. **Compactions** as steps named `compaction`. Every call is ordered by its start.

**With content on**, the run's input is the prompt and its images and its output the last reply; each model call carries what it was given (above, *Model calls*) and its reply; each tool call its input and result; each subagent's step its task and its own last reply; each compaction's step its summary, as its output. The SDK sends them only where the project's content mode is `on`: a fresh client has heard no answer naming the mode (`Telmoni-Content-Mode`), so it first asks with an export of no spans. It puts each image to `/v1/media/<sha256>` once a run, with the key, though the run's input and its first call's both hold the prompt's, and sends a `file` part in its place.

## Tags

Tags label a session's turns: every run carries them, in every content mode, and none is derived from a path. They come two ways (`tags.ts`):

- **Asked for**, through the `tag` skill. Typed, `/telmoni-observability:tag repo=telmoni`, it is the prompt row's `<command-args>` (`tag_command`), since a typed skill calls no tool; asked in plain words, Claude calls the `Skill` tool with `skill` `telmoni-observability:tag`, whose `args` are the one input read beyond a skill's name (`tool_uses`). The skill's own text tells Claude only to reply in a line: nothing runs. The words are split at whitespace, so a value holds no space: `key=value` sets, `key=` takes back, a word without `=` is dropped, in the order asked. A tag asked for holds from its turn to the session's end; the tags in force before the first turn not yet sent are kept in the session's state, so each later hook's turns carry them, a turn already sent keeping what it went with, and a replaced transcript starting over with none.
- **The file**, `.telmoni-tags.json`, in the folder the turn's opening row was written in (its `cwd`) or the nearest parent holding one, `{"repo": "telmoni"}`. The nearest entry decides: a regular file of at most 64 KiB, read never through a link (`O_NOFOLLOW`) nor waiting on a pipe swapped in (`O_NONBLOCK`), a JSON object with an optional byte-order mark; an entry by that name that is not a plain file, or cannot be read, leaves the turn with no file tags, never a parent's in its place. The folder and the path are never kept, sent or logged.

An asked tag wins over the file's for its key, and taking it back lets the file's apply again. Each is held to ingest's rules: a key of 1 to 64 letters, digits, `_`, `.` or `-`, never a `:`, which the console's `key:value` filter splits on, and never `skills`, the plugin's own; a value of up to 256 characters, with no control character, encodable as UTF-8. A run carries 32 at most, `skills` first. A tag that breaks a rule, or one past 32, is dropped with one line a session for each rule in `hook.log`, naming the rule, never the tag; no turn waits or fails for one.

## Configuration

The worker reads every setting (`settings.ts`, `readSettings`), once a hook; the hook itself reads only the variables that mark another editor and where the state lives.

- **The key.** `TELMONI_API_KEY` in the environment Claude Code started in, a shell's or a repository's `.claude/settings.json` `env` block, where it is set and not blank; else the plugin's own, `CLAUDE_PLUGIN_OPTION_TELMONI_API_KEY`. A project key with the `ingest` scope. Without one, the worker logs once a session that there is none, and stops.
- **The endpoint.** `TELMONI_ENDPOINT` beside an environment key, `CLAUDE_PLUGIN_OPTION_TELMONI_ENDPOINT` beside the plugin's own; blank is `https://api.telmoni.com`. The SDK's `Config` checks it; one it refuses is logged once a session, by the SDK's words, which name at most the host, and the run is kept.
- **Content.** `captureContent` in the SDK's `Config`, taken beside the key too: the plugin's own `CLAUDE_PLUGIN_OPTION_TELMONI_CAPTURE_CONTENT`, on at `true` alone, as Claude Code hands a boolean setting; or, beside an environment key, `TELMONI_CAPTURE_CONTENT`, on at `1` alone with Unicode's White_Space trimmed, as the SDKs read it. An environment key never takes the plugin's switch, nor the plugin's key the environment's.
- **Scrubbing.** `scrub_secrets` and `scrub_pii` in the SDK's `Config`, taken beside the key too: the plugin's own `CLAUDE_PLUGIN_OPTION_TELMONI_SCRUB_SECRETS` and `CLAUDE_PLUGIN_OPTION_TELMONI_SCRUB_PII`, off at `false` alone; or, beside an environment key, `TELMONI_SCRUB_SECRETS` and `TELMONI_SCRUB_PII`, off at `0` alone with Unicode's White_Space trimmed. Both on otherwise: before content leaves, the SDK replaces each secret, and each piece of personal data (an email, a phone number, a card number, an IP address, a home folder's path), with a marker such as `[secret: aws_key]` or `[pii: email]`, counted on its span (`telmoni.scrubbed`); no pattern finds a name or a street address. The plugin scrubs nothing itself: it hands both switches to the SDK it bundles.

A key never goes to an endpoint, nor takes a switch, set somewhere else: so a repository that names its own key reports to its own project, and one that names only an endpoint gets no one's machine-wide key.

## What is sent and what never is

With content off, a run holds kinds, ids, times, counts, flags, plain names, error kinds, the version of Claude Code, the skills run and the tags set; nothing said in the session is held in any value the plugin builds. Never, in any mode: the working folder or any path as a field of its own, the transcript's path, the tags file's path, a `redacted_thinking` block, `toolUseResult`, a meta file's `description`, a handed-back report's text, a blocking hook's reason or command, a session's title, anyone's email, the hook payload's `last_assistant_message` or `cwd`, an error's message, the key, but as the SDK's `Authorization` header. With content on, the conversation above, with any path written in it, which the SDK sends only where the project keeps content; a turn waiting to be sent keeps its conversation in the state file until it goes. The log names no key, tag, text or path: a session by the first 8 characters of its id, a run by the first 8 of its id.

## State and the log

The plugin's folder is `CLAUDE_PLUGIN_DATA`, the one Claude Code keeps for it across updates, where that is an absolute, writable folder; else `telmoni` under `CLAUDE_CONFIG_DIR`, where that is absolute, or `~/.claude`. It is made, or closed, to its owner alone (0700), and every file in it is 0600. In it:

- `<session>.json`, the session's state (`state.ts`): `offset`, the byte where the first turn not yet sent begins; `sent`, the newest 500 run ids sent; `pending`, the runs Telmoni could not take yet, in order, with their conversation where content is on, the newest 200; `warned`, which once-a-session lines were written; `destination`, a 16-hex digest of the endpoint and key the session sends with; and `tags`, those asked for before `offset`. It is saved as each run is sent, refused or kept, at most once a second, and always at the end: written to `<session>.json.<pid>.tmp`, synced and renamed over the last, so a worker killed partway, or a power cut, sends nothing twice. A state that cannot be read is left as it is and the session sends nothing, logged: read as new, it would send the whole session again and lose its kept runs.
- `<session>.pending`, beside a state that still holds runs, so a hook finds what is left to send without reading every state.
- `<session>.lock`, there while a worker is at work on the session: made only where none is (`wx`), holding its holder's token, `<pid>:<uuid>`, freshened every 10 s while held and removed as it is let go, a holder removing only a lock that holds its own token. A holder that dies leaves it: a hook takes it at once where its pid names no live process, else once it has gone a minute untouched, which a reused pid cannot hide; one hook at a time removes a dead holder's lock, under `<session>.lock.break`, so two that judged it dead at once never remove the lock the first just took. A `Stop` or `StopFailure` waits a minute for a live holder, then logs that another hook holds the session and leaves it to the next; `SessionEnd` waits it out. A lock file of another session, neither it nor its state touched for a week, a dead hook's, is swept by any hook: taken, and let go. States are never swept: one read as missing would send a resumed session from its start, and it holds no transcript's path to tell an ended session by.
- `hook.log`: a line `<UTC time> <session> <event> <text>` for each run sent, taken in part, refused or kept, each turn held, each once-a-session warning, a tag dropped and a fault; and the worker's stderr. Past a mebibyte it is turned over to `hook.log.1`.

## Delivery and failure

Each run gets an SDK client of its own, so the SDK's once-per-client warnings are the run's; its queue has no bound (`processor: { maxQueueSize: Infinity }`), so a turn however long goes whole; a flush waits as long as the SDK's own attempts take (`flush(Infinity)`), and the client is shut down whatever happened, so the worker can exit. The client's `warn` hook hears the SDK's warnings, and the verdict (`send.judge`) is read from each one's `Warning`, its kind, status and problem type, never its words:

- **Kept, sent again**: `failed`, `export_error` or `queue_full`, a flush that timed out, or `refused` with a status not final: Telmoni out of reach or busy, its database down (`500` with `/errors/internal/database`), the key or the endpoint refused (`401`, `403`, `404`). So is a run whose endpoint the SDK's client refuses. Anything not delivered keeps the run, whatever else was refused beside it.
- **Refused for good**, logged and remembered as sent: `refused` at `400` or `413` for what the run holds, `402` for the organization's standing, `500` for a fault of Telmoni's own; a run the SDK itself refuses (`TypeError`, `RangeError`, `QueueFullError`); and a kept run that no longer builds, written by an older version of the plugin, so the session's later runs still go. A run the Python version of the plugin kept is read as this one keeps its own: the state's shape, the run ids and the destination's digest are the same.
- **Taken in part**, logged: `dropped`, `span_refused`, `said`, `too_large`, `trimmed` or `upload_failed`. Anything else (`input`, `mask_failed`) counts as sent.

A kept run goes again before any new one at the session's next hook, the later turns queued behind it unsent. Since a session's last hook has no next one, the next hook of any session that left nothing kept of its own sends what other sessions left, the longest waiting first, each under that session's lock taken without waiting, and stops at the first run still not delivered. A session's runs go only where its own key sent them: another session's hook passes over a state whose `destination` is not its own, so a repository with its own key and endpoint neither receives nor sends another project's runs. Past 200 kept runs the oldest go, and the log says how many. Offline, then, a turn waits on disk, and a machine that never reaches Telmoni again keeps its newest 200.

**When Claude Code moves a format.** Every read is tolerant: a field missing or of another type reads as none, a row not understood is passed over, a name not plain is `unknown`, and nothing fails the hook. So a moved field shows as a run with less in it, not an error: a renamed marker could open a turn where there was none, or a notice no longer answering its call could hold a turn to the session's end, the `held` lines saying so. The fixtures name the Claude Code version each shape was written from, so the fix is a fixture of the new shape, then the reader in `transcript.ts`.

## Testing

`npm run verify` runs `format:check` (prettier's check on `src` and `tests`), `typecheck` (`tsc` over both), `build` (tsup, from `tsup.config.ts`, bundles `src/bin/hook.ts` and `src/bin/worker.ts`, with the SDK and OpenTelemetry, into `dist/hook.mjs` and `dist/worker.mjs`, unsplit), and `test` (`vitest run`); `npm run validate` runs `claude plugin validate --strict` on the plugin and on `.claude-plugin/marketplace.json`. There is no Makefile: the npm scripts are the gate, as in the Antigravity plugin and the SDK. The suite needs `npm ci` (vitest, prettier, TypeScript, tsup, Node's types, and the SDK itself, `telmoni`, locked in `package-lock.json`) and no network: it runs the real SDK against a fake Telmoni. Until the SDK's next release that SDK is a development dependency on the core's checkout beside this one (`file:../telmoni/sdk/typescript`, built there first), as in the Antigravity plugin, since the published 0.2.0 holds no model call's messages, no step in a step and no scrubbers; CI checks the core out at `TELMONI_REF` (`ci.yml`), the commit whose SDK the committed `dist/` bundles, and builds it before the plugin. Once the release is on npm, the dependency becomes its version range.

`tests/helpers.ts` holds the fixtures, synthetic, never a recorded session:

- `Transcript` writes a session's rows as Claude Code writes them, a second apart from `2026-10-25T03:00Z`, as version `2.1.310`: prompts, image prompts, meta rows, replies with thinking, redacted thinking, tool uses and usage, results, failed, interrupted and background results, interruptions, refusals, notices, a report handed back as `2.1.314` writes one, a blocking `Stop` hook as `2.1.312` wrote one, turn companions, rows copied from another session, subagents with their meta files and transcripts, a subagent's own subagents beside them to any depth (`nested`), and a compaction's boundary and summary (`compaction`); `conversation()` writes a turn holding everything content carries, and `long_turn()` one compacted as it goes whose subagent starts one of its own.
- `Server`, given to the SDK as its transport, answers each export as told (a status, or a status and a problem type), names a content mode where the test sets one, and keeps each export, each span taken and each image put.
- `Hook` runs the worker in the test's process against a state folder of its own, the settle and lock waits shortened (`worker.waits`).
- `SECRETS` are marked phrases planted in every place a session says something, the working folder, paths, a meta file's description, copied history, a model named by a path, redacted thinking, a compaction's summary, an image's bytes and the key; `assertMetadataOnly` fails on any of them in what is sent, kept or logged.

Each suite proves its module: `payload.test.ts`, which events are read, a `StopFailure`'s kind, `busy`, another editor left alone; `settings.test.ts`, which key, endpoint and switches go together and how each switch is read, the state folder and its mode, the provider; `transcript.test.ts`, each field read and what counts as a prompt, a marker, a notice, a tag command, a compaction's summary, a plain name, and the parts content reads; `turns.test.ts`, how turns are cut, what each model call is given, when a compaction is kept, and when a turn is complete; `record.test.ts`, a turn as a run, its id, its steps, subagents nested to the SDK's depth and no further, a compaction's step, its `skills` tag, with content on and off, and the same turn built twice as the same record; `send.test.ts`, the verdict of each warning kind and status; `tags.test.ts`, the file's walk and refusals and the rules; `worker.test.ts`, the hook's work end to end, the SDK included: delivery, holding, kept and left runs, refusals, locks (a live holder waited on, a dead one's taken, a hook letting go of its own alone) and their sweep, state faults, nested steps and compactions under their parents, content sent only under both switches, an image put once, the scrubbers' switches in the SDK's client, and a session the Python version began going on, its run ids, its key's digest and its kept run as they were; `hook.test.ts`, the hook's own process (the worker detached, its payload by stdin), its command exiting 0 when Node fails or is missing, the manifests and versions agreeing, the hook's bundle free of the SDK, and the bundles run as Claude Code runs them.

## Release

Everything an install needs is in the repository: the manifests, the hooks file, the two bundles in `dist/`, and the `tag` skill. An install copies the repository at its head, and Claude Code names the copy by the manifest's version: `claude plugin update` replaces it only when that string changes, so a commit without a bump reaches no one installed. A release is the version bumped in `.claude-plugin/plugin.json` and `package.json`, with `package-lock.json`, which `npm version --no-git-tag-version X.Y.Z` keeps in step, in one commit on `main`; `the manifests agree` (`tests/hook.test.ts`) fails on the two differing. On that push, `.github/workflows/release.yml` checks that the manifest and `package.json` agree on a plain `X.Y.Z`, asks GitHub whether tag `v<version>` and its release exist, and, for a new one, waits for CI's run on the commit to pass; once the owner approves the `release` environment, it makes the tag through the API and cuts the GitHub release with generated notes. Every other push ends green with nothing done, as does every push while the version is `0.0.0`, which is unreleased: nothing is tagged or asked for until it is bumped. No tag is made by hand.

## Decisions

- **TypeScript, bundled and committed.** Claude Code copies a plugin as it finds it and never builds one, so the hook ships built: `dist/hook.mjs`, which loads no SDK, and `dist/worker.mjs`, which carries it, each one file that Node 22 or later runs as it is. An install needs Node alone, and fetches nothing. The cost: a build before each commit, which CI holds to by rebuilding `dist/` on every push, and some 400 KB of generated JavaScript in the repository, which `.gitattributes` keeps out of `git diff` and collapses in pull requests (`-diff linguist-generated=true`), CI's comparison failing on any difference all the same. The plugin was a Python script run by uv before, which asked of a person uv on the `PATH` or a `python3` with the SDK installed by hand, and of whoever keeps it, Python. An npm source stays out: Claude Code fetches one with `npm pack`, which the npm of October 2026's Node releases refuses, its `allow-remote` defaulting to `none`. The Antigravity plugin is built the same way: Antigravity too copies a plugin as it finds it.
- **A lock file, not the operating system's lock.** Node has no `flock`, so the lock is a file made only where none is, naming its holder's pid and freshened while held: a dead holder's lock is taken at once where its pid is gone, else once it has gone a minute untouched. The cost: a holder stalled past a minute, a machine asleep mid-send, can find its session taken, and the two then send the same turns, which ingest stores once.
- **The transcript, not the hook's payload, as the source.** The payload names the session and little else; the transcript holds every call, its times and usage, and the subagents'. The cost is reading a format Claude Code owns and can move (above).
- **Metadata only unless content is on, by construction.** With content off, nothing said in a session is read into any value the plugin builds; the tests send a transcript full of marked phrases and assert that none reaches an export, the state or the log. Content needs both the developer's switch and the project's mode, the SDK holding the second.
- **A detached worker.** Claude Code waits for a `Stop` hook and gives `SessionEnd` hooks a second and a half between them; the sending, which may wait minutes on a slow Telmoni, and the SDK's first fetch happen where neither is held up. The cost: the session never hears how a send went; the log alone says.
- **The turn as the unit, held until it cannot change.** A run sent is stored once, so a turn is sent when complete rather than amended; a background subagent keeps its turn waiting until its notice or report is answered, the log saying so at each hook that holds it. The cost: a turn shows up late, and holds every later turn behind it.
- **A model call given what is new to it.** Its input is the prompt or the tool results since the call before, never the conversation again: the reading stays a pass over the rows since the last hook, and a run grows with its turn, not with the square of it. The cost: one call's input alone is not all its model saw; the calls before it say the rest.
- **A compaction is a step only once a model call follows it.** A compaction at a turn's end, a manual `/compact` after the last reply, may land before that turn's hook reads it or after; kept, it would make the same turn two records. The cost: one with no model call after it in its turn is not recorded.
- **A client a run, kept or final by the warning's kind and status.** Warnings are the SDK's only answer, and a client warns once; one a run makes them that run's. Refusals that a second try would meet again are final, so one bad run never stops a session.
- **The key goes with what is set beside it.** An environment key over the plugin's own lets one checkout report to another project; pairing the endpoint and content switch with it, and holding kept runs to its digest, keeps a key, and a session's content, from going anywhere it was not set to go.

## Known gaps

- A moved transcript format is not detected: it shows as runs with less in them, or turns held, until a fixture and the reader catch up.
- A session that never reaches `SessionEnd`, a crash or a killed terminal, leaves its last turn unsent until the session resumes, and a turn held on a background subagent whose notice never comes waits as long, holding every turn after it.
- Kept runs are bounded at 200 a session, the oldest dropped; a session's state files are never removed, one a session.
- A subagent's transcript, and each of its own subagents', is read whole each time its turn is built.
- A subagent's own subagent still running as the turn is sent, one it started in the background, is recorded as far as it got: only a subagent the turn itself started holds the turn.
- A compaction inside a subagent, a microcompaction (`microcompact_boundary`) and a manual `/compact` between turns are not recorded; the last gets no run of its own.
- Teammates and `SendMessage` resumes have no reading of their own, their shapes unconfirmed and the feature experimental: either is a step only where a meta file names the call that started or resumed it, else that call alone.
- Without Node 22 or later on the `PATH` the hook does nothing, and says so nowhere: the command's `|| true` keeps it from the session, and no worker starts to write the log.
- Until the SDK's next release, `dist/worker.mjs` bundles the core's checkout of the SDK at `TELMONI_REF`, not a release.
